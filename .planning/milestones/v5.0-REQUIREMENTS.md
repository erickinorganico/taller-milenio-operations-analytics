# Requisitos v5.0

Autorizados por la elección del usuario de operación + análisis + agentes y su instrucción de seguir recomendaciones. Los criterios se verifican con datos desechables; aceptación comercial real requiere piloto posterior.

## Acceso e instalación

- [x] AUTH-01: Un usuario inicia y cierra sesión; las rutas privadas exigen identidad y CSRF en escrituras.
- [x] AUTH-02: Gerencia, recepción, técnico, refacciones, administración y consulta tienen permisos comprobados en servidor.
- [x] RUN-01: Una instalación vacía y una demo separada arrancan en Windows mediante lanzador documentado, sin credenciales fijas de producción.
- [x] RUN-02: Se puede exportar, respaldar y restaurar la base con comprobación de integridad y procedimiento de recuperación.

## Operación

- [x] OPS-01: Recepción registra clientes, vehículos e historial, agenda citas y crea órdenes con responsable y fecha prometida.
- [x] OPS-02: El técnico registra inspecciones y evidencia; se conserva el historial de cada orden.
- [x] OPS-03: Recepción cotiza servicios y partes; las versiones, autorización y rechazo quedan registrados; no se ejecuta trabajo sin autorización.
- [x] OPS-04: La orden transita por etapas válidas, registra tiempos y bloqueos, exige calidad antes de entrega y conserva eventos.
- [x] STK-01: Refacciones registra proveedores, compras y recepción; reservar, consumir, liberar y devolver mantienen stock coherente.
- [x] FIN-01: Administración emite comprobante administrativo desde trabajo autorizado, registra pagos parciales y consulta saldos; sin duplicados ni sobrepago.
- [x] FLT-01: Se administran contratos de flotilla, vehículos y próximas tareas de mantenimiento con vencimiento y seguimiento.
- [x] TOW-01: Se registran solicitudes de grúa, responsable, hitos y cierre con evidencia humana; sin decisión automática de seguridad.

## Datos e inteligencia

- [x] DAT-01: El usuario consulta tablas fuente con búsqueda, relaciones y exportación CSV segura.
- [x] MET-01: Métricas operativas, rentabilidad, conversión y cobranza se calculan desde registros persistentes con definiciones, cobertura y detalle.
- [x] MET-02: Faltantes de datos y ausencia de historial producen estado desconocido; no margen ni tendencia inventados.
- [x] AGT-01: Agentes de operación, cobranza y calidad recopilan evidencia actual y guardan ejecución, hallazgos y propuestas verificables.
- [x] AGT-02: Una propuesta aceptada crea una tarea interna una sola vez; responsable, vencimiento, decisión, cierre y comprobación posterior son persistentes.
- [x] AGT-03: El modo nativo invoca un modelo real por la CLI autenticada con salida estructurada validada; errores quedan visibles sin presentarse como éxito. Corrida local sintética #5 documentada; piloto real aparte.

## Entrega y comprobación

- [x] UX-01: Recepción, técnicos y gerencia completan sus recorridos en una interfaz española adaptable a teléfono, con estados vacíos y errores útiles.
- [x] QA-01: Pruebas funcionales comprueban recepción → autorización → refacciones → ejecución → calidad → entrega → pago parcial → saldo y métricas.
- [x] QA-02: Pruebas negativas cubren roles, CSRF, transición inválida, duplicados, falta de stock, sobrepago, evidencia ausente y propuestas obsoletas.
- [x] DOC-01: Manual por rol, procesos, diccionario de datos, catálogo de métricas, contratos de agentes y procedimiento de instalación/soporte corresponden al software implementado.

## Límites explícitos

Comprobantes administrativos no son facturas fiscales. No integración bancaria, CFDI, pagos en línea, mensajería externa, telefonía, compras reales ni diagnósticos automáticos sin configuración y alcance posteriores. Flotillas y grúas tienen captura y seguimiento local, no telemetría ni despacho autónomo.
