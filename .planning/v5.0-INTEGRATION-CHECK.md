## Hallazgos

### WARNING — enlace CSV visible para roles sin permiso de fuente (DAT-01, UX-01, AUTH-02)

`workshop/views.py:113` envía siempre `export_url="/data/{key}/?export=csv"` desde una lista de `CATALOG`. `workshop/templates/workshop/table.html:1` muestra el botón si existe `export_url`. Recepción puede abrir `/records/customers/` y refacciones `/records/parts/`, pero `workshop/views.py:395` exige `data_read` para `/data/<key>/`; esos roles reciben 403 al pulsar el botón. El control del servidor es correcto y no hay fuga de datos; la promesa visual de exportación queda rota. Conexión `records → data_table`: WIRED pero inconsistente para esos roles. Reparación sugerida: mostrar ese enlace solo a quien tenga `data_read`, o implementar una exportación separada con permiso acotado; añadir una prueba del enlace por rol.

### Gate de entrega pendiente, ya conocido (RUN-01, AGT-03, QA-01, DOC-01)

`artifacts/v5-package.json` aún describe 70 pruebas y `native_inference_verified=false`, y `artifacts/v5-final-package-smoke.json` corresponde a ese ZIP anterior. El código actual ya tiene recibos de 71/71 y una ejecución nativa real. La conexión **fuente actual → ZIP final → smoke final** todavía no tiene recibo vigente; no se debe atribuir al ZIP anterior los últimos flags ni documentos. Reconstruir el paquete después de actualizar documentos y repetir su smoke completa este gate. El smoke previo sí comprobó instalación offline con Python 3.12 extraído, migración, respaldo/restauración, 24 tablas y totales, sin datos del cliente.

**Orphaned exports:** ninguno entre los contratos clave. **Broken core flows:** ninguno. **Unprotected sensitive routes:** ninguna identificada. Los límites explícitos de un taller local sin CFDI, banco, mensajería, telemetría, despacho automático ni piloto real no se contabilizan como conexiones faltantes.
